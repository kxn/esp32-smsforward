# 来电与短信来源数据

固件除了手机号归属地（见 [PHONE_REGION_DATA.md](PHONE_REGION_DATA.md)）之外，还会识别另外三类号码，并把结果附在短信、来电和彩信通知的号码后面：

| 号码形态 | 例子 | 通知里的标注 |
| --- | --- | --- |
| 中国大陆手机号 | `13800138000` | 号段归属省市，如 `北京` |
| 中国大陆座机 | `01021285387` | 区号对应的城市，如 `北京`；`0755…` 为 `深圳` |
| 全国统一服务号 | `95555`、`95338`、`10086`、`110` | 机构名称，如 `招商银行`、`顺丰速运`、`中国移动`、`公安报警` |
| 106 短信端口 | `106980095533` | 机构名称（银行等以 `1069800` + 五位客服号发送），其余为 `企业短信服务号` |
| 400 / 800 企业号 | `4001234567` | `企业客服`（具体企业不对公众公布） |
| 境外号码 | `+14155551234`、`0014155551234` | 国家或地区，如 `美国/加拿大`、`香港` |

例如：

```
【接到来自01021285387（北京）的来电】
【接到来自95555（招商银行）的来电】
【收到来自106980095533（中国建设银行）的短信】
【收到来自+14155551234（美国/加拿大）的短信】
```

标注只表示号码的登记地或登记机构，不代表来电者当前的位置。未收录的号段、不可识别的号码和短号不加括号。

## 数据来源

| 数据 | 来源 | 版本 | 许可证 |
| --- | --- | --- | --- |
| 大陆座机区号 | [uiwjs/province-city-china](https://github.com/uiwjs/province-city-china) 的 `@province-city-china/district-code` | 8.5.8 | MIT |
| 国际电话区号 | Google [libphonenumber](https://github.com/google/libphonenumber) 的 `PhoneNumberMetadata.xml` | 提交 `a82c3ec0ceafc4ff71feae633a180f23e3d8d336` | Apache-2.0 |
| 国家中文名 | [uiwjs/province-city-china](https://github.com/uiwjs/province-city-china) 的 `@province-city-china/country`，另补 9 个上游缺项 | 8.5.8 | MIT |
| 服务号码 | 仓库内 `tools/data/service_numbers.tsv` | 随仓库 | CC0 |
| 95 客户服务号码 | 工业和信息化部《95 客户服务号码使用表》（工信微报发布，中国电信澎湃号转载，2020-08-27） | 2020-08 | 政府公开信息 |

服务号码只收录能核对到公开来源的号码，`tools/data/service_numbers.tsv` 的文件头列出了每个来源：中国人民银行的银行客服电话名单、国家金融监督管理总局的保险客服电话、工业和信息化部的运营商客服电话、国家邮政局的快递企业投诉电话、工业和信息化部公布的《95 客户服务号码使用表》（247 个 95 号码及其使用主体），以及各省市公开的 `123xx` 便民热线清单。拿不准的号码一律不收录，宁可显示不出名字，也不要在通知里写错机构。

95 号码按品牌名做了缩写（如"中国太平洋保险（集团）股份有限公司"写成"太平洋保险"）；`95598` 同时被国家电网和南方电网使用，因此显示为 `国家电网/南方电网`。

### 106 短信端口的识别规则

`106` 是短消息类服务接入码，由工信部或各省通信管理局分配：`1062`/`1063`/`1066` 为省内号段，`1065`/`1068`/`1069` 为跨省/全国号段，其中 `1069` 是三网合一通道。端口号是 `106` 加 8 位管理码，因此长度只有 11 位（`1065`/`1068`）和 12 位（`1069`）两种，第四位只可能是 `2/3/5/6/8/9`。

银行等机构通过 `1069` 平台端口发短信时，通行做法是 `1069800` 后面接自己的五位客服号：`106980095533` 是中国建设银行，`106980095508` 是广发银行，`106980012345` 会命中 `12345` 政务服务便民热线。固件只对这一种有公开依据的写法还原机构名，其余 106 号码一律显示 `企业短信服务号`，因为端口背后的 SP 代码无法离线核实。长度不对、或者第四位不是上述号段的号码（如 `1061234567`）不猜测，保持不标注。

国际区号取自 libphonenumber 的权威表：一个区号对应多个国家或地区时（如 `+1`、`+7`、`+44`），表中用上游标记的"主归属"名称，`+1`、`+7` 另外写成 `美国/加拿大`、`俄罗斯/哈萨克斯坦`；`+800`、`+870`、`+881` 等不落到具体国家或地区的区号显示为国际业务名称。

## 表结构与查找

`firmware/main/phone_origin_data.inc` 是生成文件，包含四张排序表（座机区号 329 条、国际区号 215 条、服务号码 290 条，以及共享的 830 条 UTF-8 标签池（9.5 KB））和 16 位标签编号。查找全部在 Flash 上做二分，不需要解压，也不占用堆。当前整份表约 32 KB 源码，编译后约 21 KB。

`firmware/main/phone_origin.c` 先把号码归一化：去掉空格、短横线、括号和点号；`+` 开头或 `00` 开头视为国际号码；`+86`、`0086` 和裸 `86` 前缀的大陆号码还原成 11 位后再查号段表。归一化之后按下面的顺序判断，先命中先返回：

1. `106` 开头的 11/12 位号码：短信端口，先试 `1069800` + 五位客服号，其余显示 `企业短信服务号`。
2. 国际号码：按 3→2→1 位从长到短匹配国际区号。`+86`、`0086` 开头的号码不属于这一类：去掉国家码后按大陆号码处理，并且因为国际写法省略长途前缀 `0`，补回 `0` 之后再查（`+86 10 …` 认成 `010…`，`+86 755 …` 认成 `0755…`）。
3. 11 位、以 `1` 开头：大陆手机号，交给 `phone_region_lookup()`。
4. 3–6 位且命中服务号表：服务号码（含 `956xxx` 六位号码）。
5. 10 位且以 `400`、`800` 开头：企业客服。
6. 以 `0` 开头且长度至少 7 位：大陆座机，先按 4 位区号、再按 3 位区号查表。

## 重新生成

```sh
python tools/gen_phone_origin.py
python tools/gen_phone_origin.py --check        # 校验仓库里的生成文件是否最新
python tools/gen_phone_origin.py --area-source district-code.json \
    --metadata-source PhoneNumberMetadata.xml --country-source country.json
```

生成器会验证每个下载文件的 SHA-256。修改服务号码只需编辑 `tools/data/service_numbers.tsv` 再运行生成器。生成结果超过 64 KiB 时生成器会报错，避免无声地吃掉 Flash。

`tools/test_phone_origin.c` 覆盖了上述每一类号码的典型写法（含带分隔符、`+86`/`0086`/裸 `86` 前缀、国际写法的大陆座机 `+86 10 …`、`953xx`/`955xx`/`956xxx` 服务号、银行 `1069800` 短信端口、非法 106 号段、未收录的区号、`+999` 等无效国际区号），`python tools/test_host.py` 会连同通知文案测试一起运行。
