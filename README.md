# ESP32 短信转发器

把插在设备里的 SIM 卡收到的短信、来电和彩信到达提醒发到飞书私聊。你可以在飞书里发短信、引用原通知回短信、管理无条件呼叫转移，也可以打开设备的局域网管理页。设备通过 Wi‑Fi 直接连接飞书。

本文适用于 v1.3 及更新固件。

## 开始前

| 项目 | 要求 |
| --- | --- |
| 设备 | 目前仅实测 **ESP32‑S3 + 两个 ML307A** 的双卡板，使用 8 MB Flash、8 MB 八线 PSRAM。固件按该板的模组接线编译。ESP32‑C3 版和其他接线的板子尚未验证，请勿刷入本发布包。 |
| SIM 卡 | 在兼容双卡板上可以只插一张卡，也可以插两张。请确认卡已开通所需的短信、语音或彩信业务，并在关机时装卡。 |
| 网络 | 准备可访问飞书开放平台的 2.4 GHz Wi‑Fi。进入局域网管理页时，手机或电脑需要能访问设备所在的局域网。 |
| 刷机 | 准备一台电脑、一根可传数据的 USB 线，以及 Python 3.10 或更新版本。 |
| 首次配置 | 在支持 Web Bluetooth 的电脑或 Android 手机上用 Chrome 或 Edge 打开配置页。iPhone 和 iPad 的 Safari 不支持此配网方式，可在电脑上完成首次配置，再用手机打开局域网管理页。 |
| 飞书 | 准备一个能创建企业自建应用的飞书账号。组织开启应用审批时，由管理员审核发布。 |

## 1. 下载并刷入固件

1. 在发布页下载适用于你的硬件的 `esp32-smsforward-s3-ml307a.zip` 并解压，保留解压后的目录结构。 [GitHub Releases](https://github.com/kxn/esp32-smsforward/releases)
2. 用数据线把设备连到电脑，找到新增的串口。Windows 在「设备管理器 → 端口（COM 和 LPT）」查看。macOS 可执行 `ls /dev/cu.*`，Linux 可查看 `/dev/ttyACM*` 或 `/dev/ttyUSB*`。关闭占用串口的工具。
3. 在解压目录打开终端。把 `COM3` 换成实际串口。如果启动 Python 用的是 `py` 或 `python3`，下方命令也相应替换 `python`。安装刷机工具，然后确认识别到的是 ESP32‑S3 和 8 MB Flash。

   ```sh
   python -m pip install --upgrade "esptool>=5,<6"
   python -m esptool --chip esp32s3 --port COM3 flash-id
   ```

4. 首次覆盖原厂固件前，读取并保存整片备份，以便将来恢复原厂状态。备份可能含密码或短信，请妥善保管。

   ```sh
   python -m esptool --chip esp32s3 --port COM3 read-flash 0x0 0x800000 my-device-backup.bin
   ```

5. 在同一目录运行一次刷机命令。`flash_args` 随包提供，包含本版本的镜像地址和参数。等待工具写入并校验。若设备没有自动启动，按 RESET/EN 或重新插拔 USB。

   ```sh
   python -m esptool --chip esp32s3 --port COM3 --baud 115200 write-flash '@flash_args'
   ```

如果工具一直停在 `Connecting...`，可以手动进入下载模式。按住 BOOT，短按并松开 RESET/EN，再松开 BOOT。设备没有 RESET/EN 按键时，可在断电后按住 BOOT 接通 USB，待串口出现再松开。进入下载模式后串口号可能变化，重新查看并运行命令。 [Espressif ESP32‑S3 刷机文档](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/)

## 2. 用蓝牙连接设备和 Wi‑Fi

1. 开启电脑或 Android 手机的蓝牙，靠近已正常启动的设备，在 Chrome 或 Edge 打开蓝牙配置页。 [GitHub Pages 配置页](https://kxn.github.io/esp32-smsforward/)
2. 点击「连接设备」，在浏览器弹窗里选中名称以 `SMSF-` 开头的设备。按浏览器提示允许访问蓝牙，无需先到系统蓝牙设置里配对或输入 PIN。选中设备后，页面会读出概览。
3. 进入「网络」，用「扫描网络」选择 Wi‑Fi，或手动输入 Wi‑Fi 名称。填写密码，保持「自动获取 IP（DHCP）」开启。
4. 点击「保存并连接」，回到「设备概览」。等 Wi‑Fi 显示已连接且有 IP 地址后，继续配置飞书。首次配置期间可随时通过蓝牙读取和保存设置。

也可以在电脑上自托管随新版固件包提供的配置页。在解压目录运行 `python -m http.server 8765 --bind 127.0.0.1 --directory web`，保持终端打开，再在同一台电脑上用 Chrome 或 Edge 访问 `http://127.0.0.1:8765/`。

## 3. 创建并绑定飞书机器人

1. 进入飞书开放平台「开发者后台」，点击「创建企业自建应用」。为应用填写一个便于查找的名称，例如「我的短信转发器」。进入应用后，在「添加应用能力」中添加「机器人」。 [飞书开发者后台](https://open.feishu.cn/app)
2. 打开「权限管理」，搜索下表中的权限标识，在应用身份（`tenant_access_token`）下开通所需权限。 [飞书消息和媒体资源权限](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1) · [飞书权限标识](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group?lang=zh-CN)

   | 权限标识 | 用途 |
   | --- | --- |
   | `im:message.p2p_msg:readonly` | 获取用户发给机器人的单聊消息，供设备接收命令和引用回复。 |
   | `im:message:send_as_bot` | 以应用的身份发消息，供设备发通知并回复命令。 |
   | `im:resource` | 获取与上传图片或文件资源。需要转发彩信图片或附件时开通。 |

3. 在应用的「凭证与基础信息」复制 **App ID** 和 **App Secret**。回到设备配置页的「飞书」标签，填入同一个应用的两项凭证，点击「保存飞书配置」。App Secret 保存后会清空输入框。设备用已保存的 Wi‑Fi 取得局域网 IP 且飞书长连接上线后，会记录首次配置完成并自动关闭蓝牙。配置页此时会断开，可以继续下一步。
4. 回到飞书开发者后台，打开「事件与回调 → 事件配置」。在「订阅方式」选择「使用长连接接收事件」并保存，再点击「添加事件」，选中「接收消息」`im.message.receive_v1`（事件版本 2.0）并确认保存。如果平台提示设备尚未连接，稍等片刻，或在蓝牙配置页的「设备概览」检查 Wi‑Fi 和飞书状态。设备会主动连接飞书。 [飞书长连接事件配置](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)
5. 打开「应用发布 → 版本管理与发布」，点击「创建版本」，填写版本号和更新说明。编辑「可用范围」，加入负责操作设备的飞书账号，保存后点击「申请线上发布」，等待发布完成。以后修改权限、机器人能力或事件订阅，也要创建并发布新版本。 [飞书自建应用发布与审核](https://open.feishu.cn/document/best-practices/intro-to-custom-app-review?lang=zh-CN)
6. 用负责操作设备的账号在飞书客户端搜索机器人名称，打开**与机器人的私聊**，发送 `/help`。看到命令列表后，再发 `/sims` 检查卡号，发 `/web` 打开管理页。

设备会绑定收到的第一条合格的机器人私聊事件，此后向该账号发送通知并处理该账号的私聊命令。首次发布把可用范围设为设备操作者，并由该账号先发送 `/help`。每台设备使用独立的飞书应用，避免同一应用下的多台设备随机分得消息。 [飞书长连接分发机制](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)

## 4. 确认卡号并在飞书操作

- **单卡**时，插卡所在槽填写或核对本机号码，空槽的号码栏留空。用 `/sms` 或 `/forward` 时仍须写出在用卡的完整号码。
- **双卡**时，分别核对两槽与手机号的对应关系。每条发送或呼转命令用完整本机号码选卡。两槽号码重复时，设备会拒绝执行。
- 如果设备概览或 `/sims` 显示“本机号码未知”，点击概览卡片上的“前往卡槽手动填写”，或直接打开管理页的「卡槽」，给对应槽填写 SIM 的真实完整号码并点「保存卡槽」，再发 `/sims`。卡槽名称只用于辨认，不能代替号码。SIM 自身能提供有效号码时，设备优先采用 SIM 读到的号码。更换或对调 SIM 后，请核对手动填写的号码。
- 本机号码支持中国大陆 11 位手机号，也可在 11 位号码前带 `86` 或 `+86`。卡槽数字、卡名和尾号均无法选卡。填写国际目标号码时使用 `+` 和完整国家码，号码中间不加空格或连字符。

| 用途 | 在机器人私聊里发送 |
| --- | --- |
| 查看帮助 | `/help` |
| 刷新并查看本机号码 | `/sims` |
| 发送短信 | `/sms <本机完整手机号> <目标号码> <短信正文>` |
| 查询无条件呼转 | `/forward <本机完整手机号>` |
| 开启或更新无条件呼转 | `/forward <本机完整手机号> <目标号码>` |
| 关闭无条件呼转 | `/forward <本机完整手机号> off` |
| 获取局域网管理链接 | `/web` |

下面是用法示例。复制一行后，将整个尖括号及其中的文字替换成自己的号码，再发送。

```text
/sms <本机完整手机号> <收信号码> 这是一条测试短信。
/forward <本机完整手机号>
/forward <本机完整手机号> <接听号码>
/forward <本机完整手机号> off
```

短信正文可以包含空格和换行。发送后查看飞书回执，提交成功表示模组已接受发送。遇到长短信部分提交或回执超时，先核对收信方实际收到的内容，再决定是否重发。呼转命令只接受一行，开关状态以运营商返回的查询结果为准。设置成功后，可用另一部手机实际拨一次验证。

要**回复收到的短信**，在飞书对原短信通知使用「回复」，直接输入回复正文。设备会核对原收件 SIM 的身份并使用这张卡，发送给原发件人。旧通知没有可验证的 SIM 身份、原卡已拔出或身份核验失败时，请改用 `/sms` 指定完整号码。引用回复提示无法核实两张 SIM 的身份时，单卡用户也可用 `/sms` 重试。

## 5. 用 `/web` 打开局域网管理页

1. 让手机或电脑连上设备所在的局域网。比如手机和设备连同一个家庭 Wi‑Fi，电脑可以通过同一路由器的网线接入。
2. 在已绑定的飞书私聊发送 `/web`，点开回复里的完整链接。必要时选择用系统浏览器打开。局域网入口可以直接查看状态、修改网络和飞书、设置卡槽和时区，以及重启设备。
3. 链接带有授权 token，打开后页面会把它从地址栏移除，只保存在当前浏览器标签页的会话里。原标签页刷新可以继续使用。token 由芯片的 Wi‑Fi MAC 地址派生，重启、断电、升级固件、恢复出厂设置和整片擦除都不会改变，所以同一台设备的链接可以长期保存；只有更换芯片（或改写芯片里的 MAC）时才会换新。如果更换 Wi‑Fi 或设备的 IP 地址发生变化，把旧链接里的 IP 换成新地址即可。

链接就是这台设备的管理凭证。它由公开算法和设备 MAC 推导而来，知道 MAC 的人也能算出同一个 token，请不要把它当作密码使用，也不要转发给他人。局域网入口使用 HTTP，请在可信的家庭或办公局域网内使用，避免经路由器端口转发暴露到公网。更换 Wi‑Fi 时填写新密码，普通保存时空白的密码框会沿用已保存的值。

设备会在首次连通 Wi‑Fi 和飞书后保持蓝牙关闭，即使重启或断网。此时如果无法从飞书取得 `/web` 链接，可通过下方的 USB 控制台修改 Wi‑Fi 或飞书设置。

### 断网期间的短信和来电

飞书或外网不可用时，设备不会丢短信：收到的短信和来电通知先在内存缓存（PSRAM）里排队，正文在收到那一刻就写好，所以补发出来的仍是当时的收信或来电时间。缓存只在必要时才整块写进存储分区——收到第一条待补发消息时、累计到 8 条时、距上次写入满 10 分钟时、SIM 卡快满时以及重启前各写一次，不会每条短信都写一次 flash。缓存最多保留 256 条（占用约 2 MB PSRAM，与芯片上闲置的 8 MB PSRAM 相比留有余量），超出后先丢弃最早的并在管理页计数。飞书恢复后缓存按原顺序补发；已写入存储分区的内容断电后也会继续补发，只有刚收到、还没写入的少量来电通知可能在断电时丢失（短信本身仍在 SIM 卡上）。局域网管理页的「待补发」卡片显示还有多少条在等发送，「上行网络」卡片显示外网是否可达、已异常多久，以及 DNS 和 TCP 探测各自的结果。彩信只发通知、正文另外下载，通知仍以 SIM 卡为队列（补发后自动删除），所以长时间断网时彩信通知会占用 SIM 卡槽位，但恢复后能补发，不会丢。状态接口里的 `sms.journal_ok` 表示去重日志是否正常，`false` 时说明日志槽写入失败，重启前后可能重复推送同一条；`sms.sweep_ms` 是 SIM 卡重扫的当前间隔（空转时会从 30 秒逐步退到 5 分钟）。

通过蓝牙或局域网连接设备后，在「设备概览 → 运行监控」可查看 CPU 平均占用、各核占用、芯片内部温度、可用内存和自开机以来的运行时间。设备每 5 秒统计一次 CPU 占用，并在窗口结束时读取芯片内部传感器。温度读数代表 ESP 芯片，4G 模组和室温需单独测量。CPU 百分比表示这个窗口中运行任务的核心时间占比，首次连接请等一个完整窗口。页面上的「最近读取」是当前浏览器的时间。保持概览页在前台时约每 5 秒更新一次，切换到其他设置页或隐藏标签页会暂停采样读取。返回概览后会恢复更新。最后一个查看者离开约 15 秒后，设备停止后台采样。

设备自动省电，无需打开开关。当前实测板的 CPU 在空闲时可降至 40 MHz，有任务时可升至 160 MHz。Wi‑Fi 在路由器的广播间隔之间节电，两路 4G 模组保持监听，能继续接收短信和来电。

## 通知与彩信

| 类型 | 飞书里会看到什么 |
| --- | --- |
| 短信 | 发件号码、接收卡号码、接收时间和原文。原文保留换行。 |
| 来电 | 设备检测来电后尝试挂断，并在确认挂断后发送主叫号码、接收卡号码和时间。主叫号码读不到时显示「未知」。如果运营商先将来电转往其他号码，设备可能看不到振铃。 |
| 彩信 | 先发到达通知。可取回时，支持的文本和图片会以回复形式出现在原通知下。 |

中国大陆号码显示为 11 位。国际号码或服务短号通常保留原样。飞书通知经 Wi‑Fi 发送，接收普通短信和来电依赖 SIM 的移动网络。

自 v1.2 起，设备用固件内置号段表离线查询中国大陆手机号的归属地。查到时，短信、来电和彩信到达通知会在发件或主叫号码后附上省市，例如 `【收到来自1321300XXXX（河南郑州）的短信】`（尾号已隐藏）。归属地只反映号段记录，通知不显示运营商或号码使用者的实时位置。 [号段数据来源与更新方法](docs/PHONE_REGION_DATA.md)

自 v1.3.5 起，座机、服务号码和境外号码也会标注来源：座机显示区号所在城市（`【接到来自01021285387（北京）的来电】`），全国统一服务号显示机构名称（`【接到来自95555（招商银行）的来电】`、`10086` 显示「中国移动」、`12345` 显示「政务服务便民热线」），400/800 号码显示「企业客服」，境外号码显示国家或地区（`+14155551234` 显示「美国/加拿大」）。查不到时沿用原通知格式。

自 v1.3.6 起，服务号表扩充到工信部《95 客户服务号码使用表》收录的 247 个号码（`95338` 顺丰速运、`95583` 中国国际航空、`956000` 利宝保险等），并识别 `106` 短信端口：银行等机构常用 `1069800` 加五位客服号发送通知，`106980095533` 会显示「中国建设银行」，其他 106 端口显示「企业短信服务号」，长度或号段不符合规划的 106 号码不加标注。 [来源数据与判定顺序](docs/PHONE_ORIGIN_DATA.md)

彩信正文自动下载使用**收件 SIM 的蜂窝彩信服务**，上限为 **2 MiB（2,097,152 字节，含正文、图片和附件的整条彩信）**。固件内置中国移动、中国联通和中国电信的彩信接入配置，由设备自动选择。设备确认 SIM 处在归属运营商网络时才尝试下载。漫游或无法确认归属网时仅发送到达通知，停止蜂窝下载。超过上限、运营商已停止提供彩信业务、取回失败或飞书缺少媒体权限时，都可能只看到到达通知。

彩信正文、媒体转发和漫游阻断已有主机测试覆盖，运营商真实网络的端到端彩信下载验证仍待完成。

## 升级与恢复

### 从 v1.1 或 v1.2 升级到 v1.3

从发布页下载 `esp32-smsforward-s3-ml307a.zip`，按第 1 节用 USB 刷入一次 v1.3，安装支持网页升级的分区表和引导程序。按包内 `flash_args` 写入会保留 Wi-Fi、飞书凭证和历史映射。刷写和升级均不要运行 `erase-flash`。 [GitHub Releases](https://github.com/kxn/esp32-smsforward/releases)

刷写前请保留本机的整片备份。已有原厂整片备份可用于恢复原厂状态。v1.3 将原厂 FAT 所在的尾部区域用于第二个应用槽，第一次网页升级写入该槽时会覆盖原厂数据。如果只需另外保留当前尾部区域，可在转换前按以下命令读取并妥善保存。恢复原厂固件仍需原厂整片备份。

```sh
python -m esptool --chip esp32s3 --port COM3 read-flash 0x600000 0x200000 factory-tail-backup.bin
```

### 从 v1.3 或更新版本通过网页升级

1. 在需要升级的版本附件中下载适配双 ML307A 板的 `esp32-smsforward-s3-ml307a.smsfw`，或从同版 USB ZIP 中解压该文件。 [GitHub Releases](https://github.com/kxn/esp32-smsforward/releases)
2. 在设备已绑定的飞书私聊发送 `/web`，打开局域网管理页。进入「系统 → 固件更新」，选择「固件包（.smsfw）」，点击「上传并更新」，再点击「确认上传」。
3. 上传时保持局域网和设备供电。设备验证并写入备用应用槽后重启，Wi-Fi、飞书凭证和历史映射保存在独立分区。
4. 设备重连飞书后刷新原管理页（IP 变了就把链接里的 IP 换成新地址），在「系统 → 固件更新」查看「当前版本」。也可发送 `/help`、`/sims` 并用备用手机发一条测试短信，确认日常功能恢复。

首次启动新版本时，设备会检查存储、配置服务和局域网管理是否就绪，并等待设备获得局域网 IP。若约两分钟内仍无法通过检查，例如 Wi-Fi 接入点暂时不可达，设备会回到之前的版本。请在网络恢复后刷新原来的管理页（IP 变了就把链接里的 IP 换成新地址）并核对版本；只有在新浏览器里打开时才需要再发送 `/web`。

网页升级使用发布页的 `.smsfw` 文件。ZIP、原始 `.bin` 和整片备份用于 USB 刷写或恢复。网页无法打开时，可用 USB 和目标版本随包提供的 `flash_args` 恢复。

### 用 USB 控制台修正离线设备的配置

用数据线连接已正常启动的设备。在电脑上运行下面的命令，将 `COM3` 换成设备的串口。刷机时安装的 esptool 已包含所需的 pySerial 依赖。

```sh
python -m serial.tools.miniterm COM3 115200 --eol LF
```

在串口终端按需输入以下命令，每条用 Enter 提交。替换整段尖括号占位符。`wifi` 沿用现有 DHCP 或静态地址设置，串口命令的 Wi‑Fi 名称和密码用空格分隔，值里不可有空格。更换为不同的飞书应用后，由设备操作者向新机器人发送 `/help` 建立绑定。

```text
wifi <Wi-Fi名称> <Wi-Fi密码>
fset <AppID> <AppSecret>
net
```

`net` 显示设备 IP、飞书长连接状态和外网探测结果。设备重新上线后直接刷新原来的管理页即可；在新的浏览器或标签页打开时才需要发送 `/web` 取链接。按 Ctrl+] 退出串口终端。

### 恢复出厂设置

在飞书私聊发送 `/web`，打开获得授权的局域网管理页。进入「系统 → 恢复出厂设置」，阅读对话框，再选「确认恢复出厂」。选择「取消」或按 Esc 可关闭对话框。恢复出厂会清除 Wi‑Fi、飞书凭证和绑定、卡槽设置、引用映射及去重记录，保留当前固件和 SIM 卡内的短信。设备会重启并重新开放蓝牙配网。

如果要回到刷机前的固件和数据，请用自己事先保存的整片备份，在同一台设备的下载模式下写回 `0x0`。写回会覆盖备份之后的设备配置和状态。

```sh
python -m esptool --chip esp32s3 --port COM3 --baud 115200 write-flash 0x0 my-device-backup.bin
```

## 常见问题

| 现象 | 检查办法 |
| --- | --- |
| 电脑没有出现串口 | 换可传数据的 USB 线，确认使用板子的 ESP32 USB 口。拔插对照串口列表，必要时按刷机章节手动进入下载模式。 |
| 串口被占用或刷写中断 | 关闭串口监视器和其他刷机程序，重新确认串口号。检查线缆与供电，保持 `115200` 波特率重试。 |
| 配置页找不到 `SMSF-` 设备 | 首次配置时，确认设备已正常启动，靠近设备并开启电脑或手机的蓝牙。已经完成首次配置的设备请通过 `/web` 管理，离线时可从 USB 控制台修改设置。 |
| Wi‑Fi 连不上 | 核对 Wi‑Fi 名称和密码，确认路由器启用了 2.4 GHz，首次配置保持 DHCP 开启。 |
| 飞书显示离线或命令无回复 | Wi‑Fi 连上后还需能访问飞书。核对设备里 App ID 和 App Secret 是否来自同一个应用，检查「使用长连接接收事件」、`im.message.receive_v1`、所需权限和发布状态。确认由已绑定账号在私聊里发送 `/help`。 |
| 机器人在飞书里搜不到 | 检查应用有没有添加机器人、版本是否已发布、自己的飞书账号是否包含在应用可用范围内。 |
| `/web` 链接打不开 | 检查手机或电脑与设备所在网络能否互访。访客 Wi‑Fi 有时会隔离设备，手机也可能走移动数据。先在同一标签页刷新；设备 IP 变了就把链接里的 IP 换成新地址。确实需要新链接时再发送 `/web`，并保留链接的 `http://`。 |
| `/sims` 号码未知，短信或呼转失败 | 先确认有卡的槽已经注册网络，再在网页的「卡槽」补填真实本机号码。核对号码唯一、命令包含完整本机号，以及 SIM 套餐允许发送短信或设置呼转。若设备提示刷新失败，等模组恢复后重试。 |
| 只收到彩信提醒 | 核对是否处于漫游、彩信大小是否在 2 MiB 以内、SIM 是否仍开通彩信，以及 `im:resource` 随应用版本生效。 |
| 通知时间不对 | 看「设备概览」中的时间同步状态，必要时到「系统」检查时区。北京时间选择 UTC+8。 |
| 断网一阵后飞书没有自动恢复 | 设备只在**外网真的不可达或时钟没同步**时才逐级升级，链路本身正常时仍由每 5–8 秒的重连负责。外网不可达时升级顺序是：约 2 分钟后重启时间同步 → 5 分钟续租 DHCP → 10 分钟重新关联 Wi‑Fi → 20 分钟再续租一次 DHCP → 约 45 分钟仍不通才受控重启一次，两小时内不会重复重启；两次动作之间至少间隔 45 秒，避免来回折腾。「上行网络」卡片分别显示 DNS 和 TCP 探测结果，可以区分「只是 DNS 有问题」和「TCP 都被挡住」，并显示已异常多久。如果 `net.internet_ok` 一直是 `false`，问题在路由器或宽带侧。如果只是时钟没同步而外网通畅，设备只反复重试时间同步，不会因为 NTP 被封就一路升级到重启（每 10 分钟再试一次）。阈值以 `firmware/main/net_health_policy.h` 为准。 |
| 断网期间收到的短信在哪 | 恢复后自动补发，正文保留收到时的时间；管理页「待补发」显示积压数量。已写入存储分区的内容断电后也会继续补发；刚收到、还没来得及写入的少量来电通知可能在断电时丢失，短信本身仍留在 SIM 卡上。 |

反馈问题时，请提供板子型号、固件版本、浏览器及系统，以及能复现的步骤。分享截图前遮住手机号、设备和网络标识、飞书凭证、管理链接和短信内容。 [GitHub Issues](https://github.com/kxn/esp32-smsforward/issues)

## 从源码构建（可选）

使用预编译固件时，可跳过本节。开发和实板测试使用 ESP-IDF 5.4.0。在已启用 ESP-IDF 的终端进入源码目录，运行以下命令。刷机后可用 USB 串口监视器输入 `info`，查看实际运行的镜像标识。

```sh
cd firmware
idf.py set-target esp32s3
idf.py build
python ../tools/pack_update.py build
idf.py -p COM3 flash monitor
```

打包命令在当前目录生成 `esp32-smsforward-s3-ml307a.smsfw`，可选择在命令末加上自定义的 `.smsfw` 输出路径。请传入本次构建使用的目录。如果用 `idf.py -B <目录>` 构建，打包时也传入该目录。打包工具会核对镜像中的项目、版本和板型标识，以及构建出的分区表。

切换硬件前，请核对模组型号、UART 与复位引脚、Flash 分区及 PSRAM 容量。当前双 ML307A 板的引脚表在 [boards/dual_ml307a_s3.h](firmware/main/boards/dual_ml307a_s3.h)，内存与 Flash 参数在 [sdkconfig.defaults.esp32s3](firmware/sdkconfig.defaults.esp32s3)。C3 版需要独立板级配置和实机验证。

项目根目录下可运行 `python tools/test_host.py`（需要 GCC）和 `python tools/test_soak.py`。浏览器测试可用 `python -m pip install playwright`、`python -m playwright install chromium` 后运行 `python tools/test_web.py`。推送到 `main` 时 [.github/workflows/ci.yml](.github/workflows/ci.yml) 会自动跑这两套测试，改动了交付/恢复逻辑请先本地跑通。
